# 記事を作る仕組み

本人は品質の検査役ではない。**`editorial/品質基準.md` に全項目合格した記事だけを本人に見せる。**

## 手順

### 1. 素材を集める（書く前）
1. `editorial/素材マップ.md` で、その記事の「実数の出どころ」を確認し、計画資料を**全部読む**
2. 記事で使う実数を3つ以上、表にしてメモする（数字・出典ファイル・何の判断に使うか）
3. `editorial/取材メモ_*.md` から体験を拾う
4. 制度に触れるなら公式ソースで確認する（既存の確認結果があれば再利用し、出典URLを控える）
5. 足りない体験があれば `editorial/取材票.md` のルールで、本人に**まとめて1回**聞く（最大3問）。聞く前に、計画資料と作業記録で分からないか必ず探す

### 2. 書く
- `editorial/文体ガイド.md` の声で書く。`品質基準.md` の A〜D を満たすように書く。特に A（実数・捨てた案・分岐点・想定外・要約が主役でない）
- 構成は記事ごとに変える。定型ブロック（「この記事で分かること」等）は使わない
- frontmatter は `draft: true`

### 3. 査読する（サブエージェント4人に並行で依頼。モデルは Sonnet＝`standard-worker`）
次の4役に、記事本文と `品質基準.md`、素材メモを渡して査読させる。各自、該当項目に「合格／不合格＋理由＋直し方」を返させる。
1. **編集者**：A（独自性）と C（文章・文体ガイドとの一致）。「このブログでしか読めない部分」を3つ挙げられなければ不合格
2. **事実確認役（FP・社労士の目線）**：D2・D3。制度と数字を公式ソースと計画資料に当てて確認
3. **読者（その記事の想定読者、例：休職中の会社員）**：B（動けるか）。読んで次に何をするか言えなければ不合格
4. **匿名チェック役**：D1・D4。特定につながる語、年齢層が分かる数字を探す

### 3.5 見た目を確かめる
- `editorial/デザイン基準.md` の記事ページの基準（P1〜P7）を、開発サーバーで 1280px と 375px のスクリーンショットを撮って判定する。数字を比べる記事は図を入れる（P4）

### 4. 直す
- 不合格項目をすべて直し、3 をもう一度回す。全員合格まで繰り返す（最大3周。3周で通らなければ素材不足なので、手順1-5で本人に聞く）

### 5. 本人に見せる
- 見せるのは「合格した記事のURL」と「このブログでしか読めない部分3つ」と「本人にしか答えられない確認事項（あれば最大3つ）」だけ
- 本人の指摘は `editorial/取材メモ_*.md` と `品質基準.md` に反映し、次の記事から同じ指摘を受けないようにする

### 6. 公開
- 本人の了承後に `draft: false`、必要なら `src/consts.ts` の `NOINDEX` を false、`npm run build` で確認、コミット
- push は本人が PowerShell で `git -C C:\Users\kenke\dev\tatamu-blog push`
