## 週の型

| 曜日 | やること | だれが |
| :--- | :--- | :--- |
| 月 | 数字の確認（`数字の記録.md`）。その週の3本を決める（決め方は下の「選び方」）。体験を聞く必要があれば、3本分の質問をまとめて1回だけ（最大3問、`取材票.md`） | Claude→本人 |
| 月〜水 | 3本を書く（write-article の手順。1本ずつ自動チェック→4人の査読→全員合格まで） | Claude |
| 水 | 合格した3本をまとめて本人に見せる。見せるのはURL、記事ごとの「このブログでしか読めない部分」3つ、本人にしか答えられない確認（3本合わせて最大3つ）だけ | Claude→本人 |
| 木 | 本人の了承後に3本を公開。push は週に1回、ここでまとめて頼む。同じ日に3本分の X と note の投稿文を作り、投稿文書に入れる | Claude→本人 |
| 毎日 | 投稿文書のその日の分を貼る | 本人 |

- X と note：1本につき2日分（3本×2日＝6日）。各日は X のスレッド1本と、同じ判断を書き広げた note 1本（下の基本方針3・4）。残りの1日はネタ投稿のストックを書き直して使う
- 投稿文書は、いつも**2週間先まで**埋めておく。新しい記事の分で足りない日は、ネタ投稿のストックを書き直して使う（ストックは 10/23 の新ルール前の文なので、必ず書き直して自動チェックと査読を通す）
- 新しい記事を公開したら、X は次の日からその記事を先に出す。前から入っていた分は後ろへずらす
- 投稿文書を足すときは、Drive の現物を読み、新しい版を作って旧版を 99_アーカイブへ移す（移すのは本人の許可を得てから）
- 祝日や作業できない週は、記事を休んで投稿文書の補充だけにする。週の型を崩したら、このファイルに理由を書く

## 選び方（その週の3本）

0. `収益化方針.md` の「記事の選び方への組み込み」を先に当てる。2週に1本以上（2週で6本のうち1本以上）は、高単価の広告の中心になる記事にする

1. `数字の記録.md` で、検索に出始めた言葉と記事を見る。既存の記事を直すほうが早ければ、その週は記事の手直しにする
2. 新しく書くなら、`記事ネタ台帳_下書き.md` の「重なりなし・汎用性あり・書けない情報なし」から上の順に選ぶ
3. A8 で承認された広告に合う記事があれば、同じ条件のものの中で先にする（広告は数字を見てから足す。改善計画5）

## 投稿の基本方針

1. 起点はブログ。X と note は、ブログの記事を知らせるために出す
2. 1日にやることは最大2つ。X のスレッド1本と、note 1本
3. X は1本のスレッドで記事の1つの判断を伝える。3投稿、1つ目にタグ1〜2個、3つ目に記事のURL。書き方は `投稿文の基準.md`
4. note も X と同じく毎日1本出す（2026-11-04 本人判断。28日で note の表示3,766回・PV222に対し、X は1投稿2〜7回。note を毎日出していた10/15〜23は1日165〜428回、新記事の分だけにした後は29〜77回まで下がった）。中身はその日の X スレッドと同じ判断を、note 向けに書き広げたもの
   - ~~note は1記事につき要約1本。記事を公開した日の投稿文書に入れる~~（2026-10-25）
5. 広告の入った記事へ誘導する投稿には #PR を付ける
   - note の画像は、その日の note のタイトルで1枚ずつ作る（`node scripts/note-eyecatch.mjs <投稿文書.md> [開始日 M/D]` → design/export/note-MMDD.png）。記事の画像を使い回さない（2026-11-10 本人指摘：11/9 の口座振替の note に設立費用の画像を付けていた）
   - 記事のURLは、その日の話が書いてある節に向ける（`/posts/<slug>/#<見出し>`。id は本番ページで確かめる）。note の最後の一文も、その節に書いてあることを言う（2026-11-10 本人指摘：11/9 のリンクが記事の冒頭に飛んでいた）
6. 予定を変えたら、このファイルを直す。チャットだけで済ませない
